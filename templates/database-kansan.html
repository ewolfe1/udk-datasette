Working with the data — conventions worth knowing before you download

Several values in one cell
subjects, keywords, and named_entities hold multiple values in a single field, separated by a pipe (|). Split on the pipe before analysing them — a cell reading football|homecoming is two tags, not one.
Entity types are embedded in the name
Entities are commonly stored as Name [type], for example Jane Smith [faculty]. Not every entity carries a type, so treat the bracketed part as optional when parsing.
Page identifiers
A pid looks like ku-udk:101279 and is the key to the images at KU Libraries:
  • IIIF image service — https://digital.lib.ku.edu/iiif/2/{pid}~JP2
  • Thumbnail — https://digital.lib.ku.edu/islandora/object/{pid}/datastream/TN/view
  • Full page record — https://digital.lib.ku.edu/ku-udk/{number after the colon}
Metadata is machine-generated
Categories, summaries, subjects, and entities were produced with AI, and the OCR is machine-read from aged newsprint. Expect errors, and cite the original page for anything that matters. More on this.

Get it as JSON — every table and query has an API

Add .json to any table or query URL. Results come back under a rows key when you ask for _shape=objects:

  • /kansan/subject_search.json?_shape=objects&subject=football
  • /kansan/items.json?_shape=objects&_size=100
  • /kansan/stats_by_year.json?_shape=objects
import requests, pandas as pd

r = requests.get("https://example.org/kansan/subject_search.json",
                 params={"subject": "football", "_shape": "objects"})
df = pd.DataFrame(r.json()["rows"])

Every table and query can be downloaded as CSV or JSON — look for the export links at the bottom of any table or result page.
